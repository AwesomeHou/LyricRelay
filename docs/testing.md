# 测试策略

测试优先覆盖“手机听到哪句，电脑显示哪句”的可信度，不追求在 MVP 阶段把所有平台 UI 自动化。

## 测试分层

### 1. 核心单元测试

运行速度快、无设备依赖，必须覆盖：

- LRC 时间标签解析、无序标签、空行和非法标签。
- 当前行查找：开头、行间、末尾、重复时间戳。
- `playing`、`paused`、`stopped` 的位置推算。
- 播放速度变化、Seek、边界裁剪和长时间校准。
- 新 `trackId` 使旧请求失效。
- 协议字段范围、版本和未知消息处理。

### 2. 跨端契约测试

- Android 生成的 `track.state` 能被 Windows 解析。
- 缺失可选 Metadata 不导致整条消息丢失。
- 重复消息、旧 `stateVersion` 和断线后的完整状态都得到预期处理。
- 示例 JSON 始终是有效协议样例。

### 3. 集成测试

在本机或局域网模拟：

- QR 配对成功与错误 token。
- 设备发现、连接、心跳、断线、指数退避和重连。
- 歌词查询超时、无结果、格式错误和切歌期间旧请求返回。
- 状态变化到 Renderer 的完整链路。

### 4. 手工平台验证

Windows Shell 和 Android MediaSession 受系统版本及第三方播放器影响，MVP 需要维护手工验证表：

| 场景 | 预期 |
| --- | --- |
| 网易云音乐播放 | 自动识别并显示同步歌词 |
| QQ 音乐 / Spotify / YouTube Music | 能读取 Metadata 与播放状态 |
| 播放 → 暂停 → 恢复 | 歌词停住并继续，不明显跳行 |
| 拖动进度条 | 快速跳到对应歌词 |
| 上一首 / 下一首 | 旧歌词不覆盖新歌 |
| 手机离开局域网后回来 | 自动重连并重新校准 |
| Windows 亮色 / 暗色、DPI 缩放 | 可读且不遮挡托盘 |
| 无同步歌词 | 连接保持，任务栏显示明确空状态 |

## 时间轴测试建议

时间轴测试必须注入时钟，不直接等待真实时间。至少验证：

```text
position=1000ms, speed=1.0, elapsed=500ms  → 1500ms
position=1000ms, speed=1.5, elapsed=500ms  → 1750ms
paused at 3000ms, elapsed=10s              → 3000ms
seek to 120000ms                            → immediately rebase
```

## 验收门槛

在声明 MVP 可用前，核心单元测试和协议测试必须通过；至少完成首批重点播放器中的三种手工验证，并通过连续播放、切歌、暂停和 Seek 场景。任务栏渲染若因 Shell 版本失败，必须降级为不显示，而不是影响连接和歌词核心链路。
