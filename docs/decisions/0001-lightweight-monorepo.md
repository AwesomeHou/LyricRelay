# ADR 0001：采用轻量单仓库

- 状态：已接受
- 日期：2026-08-12

## 背景

LyricRelay 的 MVP 同时包含 Android、Windows、跨端协议和核心同步算法。若一开始拆成多个仓库，协议变更和文档同步会增加额外流程；若把所有代码放在一个平台项目中，又会模糊平台边界。

## 决策

采用一个仓库，按 `apps/`、`packages/`、`docs/` 和 `specs/` 分区：

- `apps/` 放平台端实现。
- `packages/protocol/` 放语言无关协议和示例。
- `docs/` 放长期有效的架构与开发规则。
- `specs/mvp/` 放需求、设计和可执行任务。

初始阶段不引入 monorepo 构建编排器、代码生成器或跨端共享运行库。协议先以 JSON 契约维护，只有重复成本真实出现时才增加生成工具。

## 结果

优点是目录简单、边界清晰、协议变更容易审查。代价是 Android 和 Windows 的模型映射需要各自维护，后续应通过契约测试保证一致性。

## 放弃条件

当构建、发布或协议版本管理出现明确的重复瓶颈时，再评估引入构建编排或代码生成，而不是预先增加基础设施。
