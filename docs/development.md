# 开发与编程规范

这份规范的目标是让 MVP 保持小、可测试、可替换。遇到规范与产品边界冲突时，先回到 [MVP 需求](../specs/mvp/requirements.md) 判断是否值得增加复杂度。

## 通用原则

- 先保证模块边界，再优化实现细节。
- 不为未来可能的功能预留复杂抽象；只有出现第二个实现时才抽象接口。
- 核心逻辑优先做成纯函数或无平台依赖的类。
- 错误要可恢复时恢复；不能恢复时给出明确状态，不静默吞错。
- 业务数据、传输数据和 UI 状态分层，不让 UI 直接读平台 API。

## Kotlin 约定

- 使用 Kotlin 官方格式，4 空格缩进。
- 类型使用 `PascalCase`，函数和属性使用 `camelCase`，常量使用 `UPPER_SNAKE_CASE`。
- MediaSession、权限和后台生命周期代码放在适配层，Reader 对外只暴露标准化模型。
- 协程作用域必须绑定生命周期；禁止在全局作用域启动长期任务。
- 可空字段按协议定义处理，不用空字符串代替未知值。
- 每个状态变化都要说明来源，不能依赖轮询猜测切歌。

## C# / .NET 约定

- 使用 4 空格缩进和文件级命名空间；类型使用 `PascalCase`，局部变量使用 `camelCase`。
- 异步方法以 `Async` 结尾，并传递 `CancellationToken`。
- `TimelineEngine`、LRC 解析和消息模型不引用 WPF、Win32 或网络库。
- Win32 句柄、UI Automation 对象和订阅必须有明确的释放/取消路径。
- 任务栏布局扫描不得放在高频渲染循环中；歌词未变化时只做轻量缓存检查，Shell 布局默认按秒级刷新。
- 任务栏渲染属于非核心适配层，窗口句柄失效、Explorer 重启或 WPF 窗口关闭只能导致歌词隐藏/重建，不得使客户端进程退出。
- 不用异常作为普通状态分支；对网络超时、歌词不存在等预期情况使用结果类型或明确状态。
- nullable reference types 保持开启，避免用 `null` 表达多个不同含义。

## 时间与状态

- 播放同步统一使用单调时钟。
- `sentAt` 只用于日志和排序辅助，不能用于跨设备播放位置计算。
- 状态事件应可重复处理；旧版本、重复消息和延迟消息不得覆盖新状态。
- 切歌时以新的 `trackId` 作为边界，旧请求和旧时间轴必须失效。
- 所有位置值使用整数毫秒；浮点只用于播放速度。

## 网络与 Provider

- 所有外部输入先做长度、范围和版本校验。
- 连接层负责超时、重试和断线；业务层不自行创建第二套重连逻辑。
- Provider 适配器不得把 HTML/网络细节泄漏给 Timeline Engine。
- Provider 不可用或没有同步歌词时，返回可区分的结果：网络失败、无结果、格式错误。
- 不把歌词来源或播放器包名硬编码到 UI 文案之外；使用配置/标准化字段。

## 日志

- 使用结构化日志，至少带 `deviceId`、`trackId`、`messageType`（如适用）。
- 默认不记录完整二维码、配对密钥、歌词全文或不必要的个人数据。
- 日志级别：`Debug` 用于开发诊断，`Information` 用于关键生命周期，`Warning` 用于可恢复故障，`Error` 用于需要处理的失败。
- 连接失败要记录原因和下一次重试时间，但不能每个 UI 刷新周期打一条日志。

## 提交与评审

- 一个提交只解决一个可描述的问题。
- 提交信息使用动词开头，例如 `add timeline engine tests`、`fix reconnect state reset`。
- 协议字段、状态机或用户可见行为变化必须同时更新文档和测试。
- 不在同一提交中顺手重排无关格式或清理无关死代码。

## 完成定义

一个功能只有在以下内容都具备时才算完成：

1. 行为边界和失败行为有文档。
2. 核心逻辑有自动化测试。
3. 需要跨端的字段已更新协议示例。
4. 设备断开、暂停、Seek、切歌至少有一条验证路径。
