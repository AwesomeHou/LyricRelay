# LyricRelay MVP 需求

## 目标

用户继续使用 Android 手机上的原音乐播放器和蓝牙耳机，Windows 自动识别当前歌曲，并在任务栏显示与手机播放进度同步的歌词。

## 用户故事

- 作为办公中的听歌用户，我希望不用操作 Windows 就能看到手机正在播放的歌词。
- 作为使用不同播放器的 Android 用户，我希望产品优先读取系统 MediaSession，而不是要求我改用新的播放器。
- 作为 Windows 用户，我希望切歌、暂停、恢复和 Seek 后歌词仍然跟手。
- 作为重视隐私的用户，我希望手机音频不被传到电脑或云端。

## 验收标准（EARS）

### R1 配对与自动连接

- 当 Windows 首次运行时，系统应显示一次性 QR 配对信息。
- 当 Android 扫描有效 QR 并完成授权时，系统应绑定这台 Android 与这台 Windows。
- 当已配对设备处于同一局域网时，Windows 应自动发现并连接该设备。
- 当连接中断时，系统应自动重试；恢复后应重新发送完整播放状态。

### R2 MediaSession 读取

- 当 Android 存在可用活跃 MediaSession 时，Companion 应读取标题、歌手、专辑、时长、播放器包名和播放状态。
- 当播放器切歌、播放、暂停或 Seek 时，Companion 应立即发布新的状态。
- 当没有可用 MediaSession 时，Companion 应发送 `track.cleared` 或保持明确的无歌曲状态。

### R3 歌词获取

- 当 Windows 收到新歌曲时，系统应使用歌曲 Metadata 查询至少一个同步歌词 Provider。
- 当 Provider 返回时间轴歌词时，系统应解析为有序时间段。
- 当 Provider 超时、无结果或返回非法格式时，系统应保持连接并显示可理解的空状态。
- 当新歌到来时，旧歌词请求返回的结果不得覆盖新歌曲。

### R4 时间轴同步

- 当收到播放状态时，Windows 应使用本地单调时钟推算当前位置，而不是要求 Android 高频发送进度。
- 当状态为暂停或停止时，系统应停止推进歌词位置。
- 当发生 Seek、恢复播放或周期性校准时，系统应重新建立时间基准。
- 当持续播放较长时间时，系统不应出现明显累计漂移。

### R5 任务栏显示

- 当存在可用同步歌词时，Windows 应只在任务栏显示当前歌词。
- 当任务栏大小、DPI、亮暗色变化时，渲染器应重新布局并保持可读。
- 当任务栏区域不可用时，系统应隐藏歌词而不影响连接、歌词获取和状态同步。
- 当用户关闭歌词显示时，系统应停止渲染但保留设备连接。

### R6 范围约束

- MVP 不得传输手机音频，不得包含账号、云同步、播客字幕、ASR、桌面悬浮歌词、macOS、iOS 或多手机连接。
- 首批兼容目标为正常使用 Android MediaSession 的主流音乐播放器，不承诺覆盖所有播放器。
